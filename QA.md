# 🔍 QA-агент — проверка продукта перед выдачей ученикам

Система, которая после каждого изменения сама прогоняет тесты, ищет баги и заранее
находит вопросы, которые зададут ученики.

---

## Зачем

Продукт отдают новичкам. Новичок копирует команды буквально, работает на чистом
сервере и при первой непонятной ошибке пишет вам лично. Один пропущенный баг — это
двести одинаковых сообщений в поддержку.

Правило системы: **если ученик ошибся, а продукт не объяснил, что именно не так —
это баг продукта, а не ученика.**

---

## Как пользоваться

### Вариант 1 — просто скажите Клоду

Сделали что-то новое и написали:

> «Готово, проверь» · «Я добавил фичу» · «Можно отдавать ученикам?» · «Найди баги» · «Что спросят ученики?»

Навык `auto-test` включается сам: прогоняет автотесты, запускает двух агентов и
выдаёт отчёт. Ничего вводить руками не нужно.

### Вариант 2 — запустить проверку вручную

```bash
bash qa/run.sh              # всё сразу
bash qa/run.sh shell        # только bash-скрипты
bash qa/run.sh node         # только Node
bash qa/run.sh docs         # только инструкции
bash qa/run.sh secrets      # только утечки токенов
bash qa/run.sh student      # только сценарии ошибок ученика
```

Код выхода `0` — блокеров нет, можно отдавать. Код `1` — отдавать рано.

### Вариант 3 — вызвать агента напрямую

- `qa-auto` — полный QA-проход: что сломано.
- `student-sim` — пять типов учеников проходят продукт: что спросят.

### Вариант 4 — автоматически на GitHub

`.github/workflows/qa.yml` гоняет проверку на каждый push. Отчёт виден прямо в
сводке запуска, без скачивания.

---

## Что проверяется

| Группа | Что ищет |
|---|---|
| **1. Bash-скрипты** | синтаксис, молчаливые падения, проверка root, захардкоженные пути, `curl \| bash` |
| **2. Node.js** | синтаксис, установка зависимостей, загрузка модулей, понятность ошибки без токена, unit-тесты |
| **3. Инструкции** | упомянутые файлы существуют, все переменные объяснены, есть раздел «что делать, если не работает» |
| **4. Секреты** | настоящие токены в коде, `.env` под гитом, дырки в `.gitignore` |
| **5. Симулятор ученика** | заглушки в конфиге, файл из Windows (CRLF), `@ник` вместо ID, пробел в токене, повторный запуск, свободный ввод продавца |

---

## Уровни находок

| | Что значит | Что делать |
|---|---|---|
| 🔴 **BLOCKER** | ученик вообще не сможет пользоваться | чинить до выдачи |
| 🟠 **MAJOR** | сломается у части учеников | чинить до выдачи |
| 🟡 **MINOR** | неудобно, но работает | когда будет время |
| 🔵 **ВОПРОС** | не баг, но ученик точно спросит | добавить в FAQ — это дешевле всего |

## Куда смотреть результат

```
qa/report/BUGS.md        ← отчёт для человека: баги + вопросы учеников
qa/report/STUDENT.md     ← проход пятью типами учеников + готовый FAQ
qa/report/findings.tsv   ← машинный список (в git не попадает)
```

## Как добавить проверку под новый продукт

Новые тесты Node:
```
qa/tests/<имя-продукта>/<что-проверяем>.test.js
```
Обычный `node:test`, без библиотек. Запуск: `bash qa/run.sh node`

Новый сценарий ошибки ученика — в `qa/checks/50-student.sh`.

Новая группа проверок — файл `qa/checks/NN-название.sh`, подключается автоматически.
Внутри доступны `pass`, `finding SEVERITY область "заголовок" "что у ученика" "как чинить"`,
`fail_with`, `skip`, `project_files`, `detect_stack`.

**Правило:** каждый найденный баг закрывается тестом. Сначала тест падает на баге,
потом чините код. Тест, написанный после починки и сразу зелёный, ничего не доказывает.

---

## Перенести систему на новый проект

```bash
cp -r qa/ .claude/ .github/ /путь/к/новому/проекту/
```

`qa/run.sh` сам определяет стек и пропускает неприменимые проверки.
Подробнее — `.claude/skills/auto-test/references/new-product.md`.

## Структура

```
.claude/
├── agents/
│   ├── qa-auto.md          # агент: находит баги
│   └── student-sim.md      # агент: играет пять типов учеников
├── skills/auto-test/
│   ├── SKILL.md            # включается сам на «готово / проверь»
│   └── references/
│       ├── severity.md     # как отличить блокер от мелочи
│       ├── attack-list.md  # чем ломать продукт
│       ├── faq-template.md # обязательные вопросы учеников
│       └── new-product.md  # подключение к новому продукту
└── settings.json           # ставит зависимости при старте сессии

qa/
├── run.sh                  # главный запуск
├── lib/harness.sh          # общие функции и уровни находок
├── checks/                 # 5 групп проверок
├── tests/                  # unit-тесты продуктов
└── report/                 # отчёты
```
