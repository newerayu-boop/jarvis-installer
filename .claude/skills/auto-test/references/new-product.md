# Новый продукт с нуля — что подключить сразу

Когда создаётся новый продукт (новая папка, новый репозиторий, новый бот),
проверка подключается до того, как написана первая фича.

## 1. Скопировать каркас

```bash
cp -r qa/ /путь/к/новому/проекту/qa/
cp -r .claude/ /путь/к/новому/проекту/.claude/
```

`qa/run.sh` сам определяет стек (node, shell, python, next, vercel, docker,
telegram-bot) и пропускает неприменимые проверки — править его не нужно.

## 2. Добавить тесты под свой продукт

```
qa/tests/<имя-продукта>/<что-проверяем>.test.js
```

Минимум для любого продукта:
- главный сценарий работает (счастливый путь);
- продукт не падает на пустом и на очень длинном вводе;
- ошибка без токена/конфига объясняет, что делать;
- результат рендерится за приемлемое время.

## 3. Добавить сценарии ученика

В `qa/checks/50-student.sh` — по одному сценарию на каждую ошибку, которую новичок
точно сделает в этом конкретном продукте.

## 4. Проверить обязательный минимум

- [ ] `.gitignore` закрывает `.env`, `*.env`, ключи, `node_modules`
- [ ] есть `X.env.example` со всеми переменными и комментарием к каждой
- [ ] в `package.json` указан `engines.node`
- [ ] README: что это → что нужно → шаги → как проверить, что работает → что делать, если не работает
- [ ] все ошибки продукта написаны по-русски и человеческим языком
- [ ] продукт переживает повторный запуск

## 5. Включить автопрогон

Файл `.github/workflows/qa.yml` уже гоняет `qa/run.sh` на каждый push.
Скопируйте его вместе с папкой `qa/`.
