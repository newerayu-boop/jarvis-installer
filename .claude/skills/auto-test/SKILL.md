# Автопроверка продукта перед учениками

Продукт отдают новичкам. Новичок не читает между строк, копирует буквально и при
первой непонятной ошибке пишет автору курса лично. Задача этого навыка — найти всё
до того, как это найдут двести учеников.

## Шаг 0. Понять масштаб изменений

```bash
git diff --stat HEAD 2>/dev/null; git status --short
```

- **Изменена одна мелочь** (текст, цвет, опечатка) → шаги 1 и 2, без симулятора.
- **Новая фича, новый файл, новый продукт** → все шаги.
- **Меняли установщик, конфиг или инструкцию** → все шаги обязательно.

## Шаг 1. Автотесты — всегда

```bash
bash qa/run.sh
```

Результат: `qa/report/BUGS.md` (для человека) и `qa/report/findings.tsv` (машинный).
Код выхода `1` означает: есть блокеры или серьёзные баги, отдавать ученикам нельзя.

Прогнать только одну группу:
```bash
bash qa/run.sh shell     # только bash-скрипты
bash qa/run.sh node      # только Node
bash qa/run.sh docs      # только инструкции
bash qa/run.sh secrets   # только утечки токенов
bash qa/run.sh student   # только сценарии ошибок ученика
```

## Шаг 2. Ручная проверка изменённого

Прочитай изменённые файлы целиком и запусти то, что изменилось, руками. Автотест
ловит известное — ты ищешь новое. Ориентиры в `references/attack-list.md`.

## Шаг 3. Два агента параллельно

Запусти обоих одним сообщением, чтобы работали одновременно:

- `qa-auto` — полный QA-проход по изменениям, ищет баги.
- `student-sim` — проходит продукт пятью типами учеников, собирает FAQ.

Первый отвечает на вопрос «что сломано», второй — «что спросят».

## Шаг 4. Новое поведение — новый тест

Каждый подтверждённый баг закрывается тестом, чтобы он не вернулся:

- Node → добавь случай в `qa/tests/<проект>/*.test.js`
- Bash / установщик → добавь сценарий в `qa/checks/50-student.sh`

Правило: **сначала тест падает на баге, потом чинишь код.** Тест, написанный после
починки и сразу зелёный, ничего не доказывает.

## Шаг 5. Ответ пользователю

Коротко и по-русски, без жаргона:

1. **Можно отдавать ученикам или нет** — одной строкой.
2. **Блокеры** — что именно сломается и у скольких учеников.
3. **Что чинить первым** — максимум три пункта.
4. **Что спросят ученики** — 3–5 главных вопросов, остальные в отчёте.
5. Пути: `qa/report/BUGS.md`, `qa/report/STUDENT.md`.

Не пиши «всё отлично», если `qa/run.sh` вернул код 1. Не пиши «протестировано»,
если не запускал.

## Справочники

- `references/severity.md` — как отличить блокер от мелочи, шкала «сколько учеников заденет».
- `references/attack-list.md` — чем ломать: пустое, длинное, чужой алфавит, копипаста, повтор, сеть.
- `references/faq-template.md` — структура FAQ и вопросы, которые задают всегда.
- `references/new-product.md` — что подключить, когда продукт создаётся с нуля.
